## Automated coverage

Core coverage includes malformed ZIPs, traversal/absolute/Windows-style paths, symlinks, duplicate central-directory names, case collisions, multiple main apps, missing/malformed metadata, oversized/deep plists, binary plists, nested apps/extensions/frameworks, malformed Mach-O load commands and fat offsets, encryption, embedded XML entitlements, CMS envelope truncation, expiration, omission of device identifiers, cancellation at a stage boundary, and retry. A synthetic archive test confirms the original bytes stay unchanged.

UI tests cover the browser-only unavailable state, synthetic inspection rendering, recovery after a failed inspection, cancellation acknowledgement, and unavailable re-signing controls, plus explicit acknowledgement for unchanged-IPA installation. They deliberately mock IPC; they do not prove native file dialogs, drag/drop, channel transport, or a physical install work. Screenshots generated by these tests are ignored local artifacts.

## Manual desktop acceptance

1. Launch the local app and choose a small synthetic IPA, then the representative company IPA. Confirm app metadata, profile expiration, Watch/framework inventory, and report details match CLI output.
2. Drop one IPA; try multiple files, an unreadable path, and an invalid archive. Confirm actionable errors, no stale results, and a usable retry flow.
3. Cancel a large inspection. Wait for acknowledgement; inspect again. Close during inspection and reopen; confirm no partial output or restored success.
4. Confirm signing and renewal remain unavailable; account/team controls follow the account acceptance procedure below. Device discovery should show real data without account access, internet requests, or pairing mutations.
5. Repeat on Windows, including non-ASCII paths. Test native window resizing and keyboard navigation. Record OS/toolchain versions and separate browser results from native behavior.

For later device acceptance, test locked/untrusted/disconnected states, service/driver absence, transfer interruption, cancellation before/after installation commits, app launch, same-identity upgrades/data retention, then push, domains, merchants, groups, keychain, and Watch separately. Never label the app compatible solely because installation completed.
